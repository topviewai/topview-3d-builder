# Timeline Clip 拖动规则

本文定义动作、运镜和运动轨迹 Clip 在 Timeline 中的统一拖动行为。

## 适用范围

规则适用于同一对象、同一类轨道中的 Clip：

- 角色动作；
- 相机运镜；
- 角色或相机的运动轨迹。

不同对象的轨道互不参与排序，也不会互相推挤。

## 预览和提交

拖动分为预览和提交两个阶段。

1. 按下 Clip 时保存原始轨道排布和文档版本号。
2. 指针移动期间，每一帧都基于这份原始排布重新计算预览。
3. 预览阶段不修改文档、历史记录、保存状态或引擎数据。
4. 松手时提交最后一帧预览结果，并只生成一条历史记录。
5. 取消、失去焦点、按 Escape 或文档版本发生变化时，丢弃预览。

被拖动的 Clip 始终跟随指针；其他 Clip 显示计算后的预览位置。

## 删除阶段

拖动逻辑在计算上分为删除和插入两步。

删除阶段只决定候选排布，不直接修改文档。

- 如果被拖 Clip 的前后都没有空隙，它属于连续片段组；删除它时，后面连续相连的 Clip 向前收拢，直到遇到第一个空隙。
- 如果前方或后方任一侧存在空隙，则保留其他 Clip 的原始位置，不提前显示删除后的收拢结果。
- 是否有空隙只根据按下时的原始位置判断，不能根据上一次预览结果判断。

这样可以避免拖动连续轨道的第一个 Clip 时，后续 Clip 先向前移动、随后又被插回的跳变。

## 插入阶段

插入参考点根据拖动方向确定：

- 向前拖动：使用被拖 Clip 的头部；
- 向后拖动：使用被拖 Clip 的尾部。

向后拖动时，参考点与目标 Clip 发生重叠后采用三段阈值：

- 重叠不超过目标 Clip 长度的 1/3：保持拖动 Clip 的指针位置，目标 Clip 向后让位；
- 重叠超过 1/3 但不超过 1/2：拖动 Clip 插入目标 Clip 当前预览位置；
- 重叠超过 1/2：拖动 Clip 插入目标 Clip 后面，目标 Clip 保持在原顺序位置。

向前拖动，以及向后拖动未进入上述三段重叠区时，按目标 Clip 的中点决定顺序：

- 前半段插入目标前面；
- 后半段插入目标后面；
- 正好在中点时按后半段处理。

目标命中区域使用原始排布，避免目标 Clip 在预览中移动后造成阈值抖动。

参考点没有命中 Clip 时，按指针位置插入空白区域：

- 空隙足够时保持指针位置；
- 空隙不足时，将后方冲突 Clip 及其连续冲突链整体向后推；
- 前方已有 Clip 时，插入位置不得早于前一个 Clip 的结束帧。

所有 Clip 的时长保持不变，Timeline 内不得产生重叠。

## 轨迹 Clip 的时间 Handler

运动轨迹 Clip 的开始和结束 Handler 用于调整 `frameStart` 和 `frameEnd`：

- Handler 拖动同样只产生预览，松手后才提交；
- 调整时间范围不改变路径点、路径方向、路径百分比和路径几何形状；
- 轨迹 Clip 的时长变化通过播放时长重新计算，不缩短路径数据；
- Handler 不能把 Clip 拉到前后相邻 Clip 的内部，边界会被限制在不重叠的位置。

## 动作 Clip 设置

选中动作 Clip 后，右侧设置面板提供：

- 时间范围：开始帧、结束帧；
- 动作裁剪：源动作起播时间和源时长；
- 播放速度；
- 是否循环；
- 循环方式；
- 原地动画。

时间范围设置遵守和 Handler 相同的最小长度及相邻 Clip 边界约束。

## 验证要求

回归测试至少覆盖：

- 前方有空隙时，拖动第一个动作不会让后续动作提前前移；
- 连续动作跨过中点后只发生一次顺序切换；
- 两个轨迹 Clip 重叠时后续轨迹只平移、不缩短；
- 拖动到空白位置时后方 Clip 正确让位；
- 动作、运镜和轨迹都无重叠、时长保持不变；
- 预览期间文档和历史记录不变，松手后只提交一次。
